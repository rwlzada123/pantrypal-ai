AI Workflow Comparison

For this assignment, I implemented the same settings feature in two different ways to compare how prompt quality affects the development process.

In the first round, I used a very short and vague prompt asking the AI to add a settings form with validation. I intentionally did not provide detailed requirements or constraints. I expected a simple implementation, but the AI produced a much more complete feature than I anticipated. It created a dedicated settings page with profile information, meal preferences, validation, local storage support, and a clean user interface. The result was functional, but because the prompt was so open-ended, the AI made many design decisions on its own. I had to manually inspect the generated code to understand what had been added and to ensure that it matched the existing structure of the project.

For the second round, I used a much more detailed prompt. Instead of asking the AI to immediately generate code, I first instructed it to inspect the repository and produce an implementation plan. The prompt also included clear requirements for validation, accessibility, local storage handling, testing, and project constraints. This resulted in a more structured workflow. The AI explained its plan before modifying the code, reused existing project data where appropriate, and added automated tests as part of the implementation.

One of the biggest differences between the two approaches was verification. In the first round, I mainly relied on manually checking whether the application worked. In the second round, the AI added automated tests and I verified the implementation by running the test suite, ESLint, and the production build. All 19 tests passed successfully, but the verification process also revealed several lint errors. Although the application worked correctly, React Hook lint rules identified state initialization that should not occur inside useEffect. Refactoring the initialization to use lazy useState resolved the warnings without changing the application's behavior. This showed me that passing tests alone does not necessarily mean the implementation is complete or follows best practices.

Another challenge during the second round was that the AI coding assistant reached its usage limit before finishing the verification phase. Instead of starting over, I continued from the partially completed implementation, fixed the remaining issues manually, and completed the verification myself. This experience highlighted the importance of understanding the generated code instead of relying entirely on the AI.

Overall, the second workflow required more preparation, but it produced a more reliable and maintainable result. The detailed prompt reduced ambiguity, encouraged planning before coding, and made the final implementation easier to verify and trust.
